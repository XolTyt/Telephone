# ClearCall

Личное приложение для качественного видеозвонка между двумя телефонами. Создать звонок → отправить одну ссылку → собеседник нажимает «Войти». Коды и ответные ссылки не нужны. Мама/другой приглашённый участник не регистрируется в сервисах.

В этой установке публичный ключ владельца уже подключён в `config/call-service.js`. Реальные облачные звонки через TURN и отдельно TURN/TLS проверены; подробности и границы проверки — в [отчёте](docs/verification.md). Повторно создавать ключ или настраивать переменные Vercel для него не требуется. Следующая инструкция нужна при переносе на другой аккаунт.

## Как устроено

Сайт и endpoint `/api/call-config` работают на Vercel. Metered Realtime передаёт сигналы подключения, а его Open Relay выдаёт TURN для сетей, где прямое соединение невозможно. Видео и аудио передаются WebRTC напрямую или через TURN, без перекодирования на сервере сигнализации. Сервер сигнализации не является видеомессенджером. Приложение не запускает запись. SDK встроен в сборку, внешние скрипты с CDN не нужны.

Камера запрашивается в 1080p, до 30 FPS; верхний предел отправки видео — 8 Мбит/с, аудио — 128 Кбит/с. Это пределы и пожелания, а не обещание несжатого видео: WebRTC сжимает поток и адаптирует его к сети/устройству. В разделе «Качество и проверка связи» показаны реальные параметры приёма/отправки и маршрут «Напрямую» / «Через TURN». Если браузер не предоставляет поле статистики, вместо него показывается прочерк или 0 FPS.

## Однократная настройка владельцем

1. Войдите в [Metered Dashboard](https://dashboard.metered.ca/v2). В новой панели разделы сгруппированы в боковом меню. Если выбран классический вид, можно снова открыть `/v2`.
2. **Realtime Messaging → API Keys → Create key → Publishable**. Это не TURN Credential и не Developers Secret Key.
3. Включите **Subscribe, Publish, Presence и Send**. Send по умолчанию может быть выключен: без него камера откроется, но обмен SDP/ICE будет отклонён.
4. Получите **публичный ключ `pk_live_…`**. Возможны два способа подключения:
   - Добавить `METERED_PUBLISHABLE_KEY` в Environment Variables проекта Vercel (Production и нужные Preview).
   - Записать публичный ключ в `config/call-service.js`. Он предназначен для браузера и по документации поставщика не является секретом. Это позволяет обойтись без дополнительной настройки Vercel.
5. Если ранее выставляли `VITE_CALL_ENGINE=livekit` или `peerjs`, удалите эту переменную либо задайте `metered`.
6. Опубликуйте **последний коммит** и назначьте его Production. Redeploy старого коммита не берёт новый код. Используйте основной публичный домен сайта; защищённый Preview может требовать входа в Vercel.
7. Обновите страницу на обоих телефонах и создайте новый звонок. Старые ссылки с 12-символьным кодом относятся к прежнему режиму.

**Никогда не записывайте сюда `sk_…` или другие секретные ключи.** Endpoint проверяет префикс и не отдаёт случайно переданный sk_-ключ. Браузеру нужен только publishable key. Для приложения требуется один аккаунт владельца сервиса, приглашённым участникам аккаунты не нужны.

При отсутствии действующего ключа приложение сообщает, что владелец не закончил настройку. Работа облачной сигнализации и TURN **не может быть подтверждена без ключа**. Не выдавайте успешный локальный тест за проверку доступа из Беларуси или другой мобильной сети.

## Проверка после подключения

1. Сначала созвонитесь между двумя телефонами по новой ссылке. Проверьте звук и видео в обе стороны.
2. Затем проверьте разные сети: Wi-Fi ↔ мобильный интернет. Не включайте VPN на телефоне, если хотите проверить доступ именно без VPN.
3. Откройте «Качество и проверка связи». Там должны появиться «Сервер подключён», «TURN получен от сервиса» (когда создаётся соединение), «Медиа подключены», реальные FPS/разрешение/битрейт.
4. Для отдельной проверки TURN можно добавить `&relay=1` к ссылке приглашения на одном из телефонов. Этот параметр заставляет его RTCPeerConnection использовать только relay-кандидаты. Успешный звонок со статусом «Через TURN» подтверждает работу ретрансляции. Без выданных сервисом TURN-данных этот тест не пройдёт.
5. При ошибке нажмите «Скопировать данные проверки» или сделайте скриншот этого раздела. В журнал не пишутся токены, SDP, адреса устройств и TURN-пароли.

Приложение не может гарантировать доступность любого провайдера из любой сети, обойти ограничения ОС на фоновую камеру или сохранить 1080p при недостаточной скорости. Финальная проверка включает настоящий звонок с телефона пользователя и телефона собеседника.

## Поведение при проблемах

- Нет ответа на получение настроек / подключение: после 25 секунд появляется понятная ошибка и повторный вход.
- Обрыв WebSocket: автоматическое восстановление с ограниченными попытками; при долгом ожидании доступен ручной повтор.
- Потеря медиасвязи: SDK запускает ICE-restart. После исчерпания попыток предлагается повторное подключение в ту же комнату.
- Смена камеры заменяет только видео. Если другой камеры нет, приложение пытается вернуть предыдущую. Микрофон и его mute-состояние сохраняются.
- Позднее разрешение камеры после выхода: полученные треки немедленно останавливаются.
- Закрытие звонка: остановка всех локальных треков, сокетов, таймеров и удержания экрана.
- Автовоспроизведение заблокировано: кнопка «Включить видео и звук».
- Третий обычный клиент приложения получает сообщение «в звонке уже два человека»; новая попытка не должна прерывать существующую пару. Это клиентская логика двух участников, а не серверная ACL.

Ссылка является приглашением, а не удостоверением личности. Комнаты используют 120-битные случайные идентификаторы; отправляйте ссылки только собеседнику. Publishable key ограничьте отдельным workspace/приложением и необходимыми разрешениями. Для широкого публичного сервиса с недоверенными пользователями потребуются серверные JWT с индивидуальными правами — текущий режим предназначен для личных звонков.

## Лимиты

По опубликованным условиям Metered: сигнализация — до 100 одновременных соединений и 100 000 сообщений в месяц; Open Relay — 20 ГБ в месяц бесплатно. Это не безлимитный TURN: качественное видео расходует гигабайты. Проверьте актуальные квоты и действия при их исчерпании в аккаунте. Нет оплаты за транскодирование, потому что приложение его не использует.

## Разработка и проверки

Node.js 22+, npm. Установка и основные проверки:

```sh
npm ci
npm run typecheck
npm test
npm run test:e2e:metered
npm run build
```

`npm run dev` запускает Vite на порту 3000, но Vite сам по себе не исполняет Vercel Functions. Для локального ручного запуска API используйте Vercel CLI или deployment. Камера на телефоне требует HTTPS; HTTP-адрес компьютера в Wi-Fi для этого не подходит.

`test:e2e:metered` поднимает локальный сервер **протокола сигнализации** и два настоящих браузера Chrome с синтетической камерой/микрофоном. В тесте используется настоящий Metered SDK и настоящие RTCPeerConnection, а не моки видеопотоков. Проверяются ссылка, двустороннее видео/аудио, микрофон при смене камеры, восстановление после разрыва сигнализации, третий участник и завершение. Тест не проверяет облачный аккаунт, настоящий TURN или сеть Беларуси — для этого нужен ключ и реальные сетевые условия.

В репозитории для сравнения сохранены прежние реализации: `VITE_CALL_ENGINE=peerjs` и `livekit`. Они не являются автоматическими скрытыми обходами и не используются по умолчанию. Их старые инструкции — в `docs/legacy-setup.md`. `npm run test:e2e` проверяет PeerJS, `test:e2e:simple` — интерфейс LiveKit.
