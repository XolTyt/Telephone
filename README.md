# ClearCall

Видеозвонок между двумя телефонами: первый создаёт комнату и отправляет приглашение, второй открывает ссылку и нажимает «Войти в звонок». Компьютер не нужен.

React 18 + TypeScript + Vite + Tailwind + PeerJS/WebRTC. Разговор передаётся напрямую, а при невозможности прямого соединения — через настроенный TURN. Сигнализация по умолчанию — PeerJS Cloud. Приложение не записывает разговоры.

## Публикация на Vercel

1. Загрузите изменения в GitHub. В Vercel создайте проект через Import Git Repository → `XolTyt/Telephone`.
2. Выберите ветку `video-call-configuration-for-quality-915df` в настройках Git / Production Branch или разверните её отдельный deployment. Корневая папка — корень репозитория, framework — Vite. `vercel.json` уже задаёт сборку и папку `dist`.
3. Можно сначала опубликовать без TURN: прямые звонки в подходящих сетях будут работать, приложение покажет предупреждение. Для мобильных сетей настройте TURN по следующему разделу.
4. В Settings → Environment Variables добавьте для Production (и Preview, если проверяете preview):

   | Переменная | Значение |
   | --- | --- |
   | `VITE_ICE_SERVERS_URL` | `/api/ice` |
   | `TURN_URLS` | `turn:turn.example.com:3478?transport=udp,turn:turn.example.com:3478?transport=tcp,turns:turn.example.com:5349?transport=tcp` |
   | `TURN_SECRET` | Тот же секрет, что `static-auth-secret` в coturn |

5. Нажмите Deploy / Redeploy после добавления переменных. Vite встраивает переменные `VITE_*` во время сборки. **Не добавляйте префикс `VITE_` к `TURN_SECRET`.** Функция `api/ice.js` выдаёт временные пароли сроком на сутки. Общий секрет остаётся только на сервере.
6. Откройте выданную ссылку HTTPS на обоих телефонах. На первом создайте комнату, отправьте приглашение на второй. Второй участник должен нажать «Войти в звонок»: это также даёт браузеру пользовательское действие для запуска медиа.

Vercel размещает сайт и функцию выдачи паролей, **но не сам TURN-сервер**. Для TURN нужен отдельный сервер или провайдер. У меня нет ваших аккаунтов Vercel/TURN, поэтому публикация и подключение оплачиваемой инфраструктуры не выполнены автоматически.

### TURN

Для своего Linux VPS с публичным IP можно использовать coturn. Пример — `deploy/turnserver.conf.example`: замените домен, общий секрет, пути к настоящему TLS-сертификату. Разрешите входящие 3478 UDP/TCP, 5349 TCP и диапазон 49160–49260 UDP в firewall сервера и панели провайдера. Если сервер за NAT, настройте `external-ip=PUBLIC_IP/PRIVATE_IP`. DNS домена TURN должен указывать прямо на сервер, без HTTP-прокси. Для особо ограниченных сетей полезен TURN TLS на порту 443 (отдельный IP/сервер, где этот порт свободен), тогда измените URL на `turns:turn.example.com:443?transport=tcp`.

Альтернатива: задайте `VITE_ICE_SERVERS_URL` как HTTPS-адрес собственного backend, который возвращает массив объектов `RTCIceServer` с временными данными провайдера. Пример ответа:

```json
[{ "urls": ["turn:turn.example.com:3478", "turns:turn.example.com:5349"], "username": "temporary-user", "credential": "temporary-password" }]
```

Для стороннего origin backend должен разрешать CORS для вашего сайта. Не помещайте секрет API провайдера в frontend. Публичный endpoint выдачи TURN-паролей стоит ограничить по частоте запросов через firewall хостинга; квоты в примере coturn также ограничивают число подключений.

### Собственный сервер сигнализации

Необязательно: `VITE_PEER_HOST`, `VITE_PEER_PORT` (по умолчанию 443), `VITE_PEER_PATH` (по умолчанию `/`) позволяют подключить свой PeerServer через TLS. Без них используется PeerJS Cloud. Его доступность влияет на начало и восстановление звонка. `VITE_PEER_SECURE=false` предусмотрено только для локальных тестов, на публичном HTTPS-сайте оставьте TLS включённым.

## Качество

По умолчанию запрашиваются 1080p / 30 FPS, до 8 Мбит/с на видео и до 128 Кбит/с на аудио. В настройках доступны другие разрешения и лимиты. Это запросы и верхние пределы, а не гарантированное качество: браузер выбирает фактические параметры с учётом камеры, кодека, скорости сети, нагрева и возможностей устройства. Видео сжимается WebRTC. При нехватке полосы браузер адаптирует поток; увеличение лимита не создаёт дополнительную скорость интернета.

В звонке отображаются реальные параметры приёма и отправки из `getStats()`: разрешение, FPS, текущий битрейт и прямой/ретранслируемый маршрут. Если браузер не предоставляет отдельные поля, отображается прочерк или 0 FPS. После смены камеры микрофон и его состояние сохраняются. При обрыве соединения гость повторяет вызов; есть ручное переподключение на обоих телефонах. Новая комната получает случайный 60-битный код, ссылка служит приглашением — отправляйте её только собеседнику.

Используйте Safari на iPhone и Chrome на Android, хорошее освещение и устойчивую сеть. Не блокируйте экран и не сворачивайте вкладку во время звонка: мобильная ОС может остановить камеру. Автоматическое подключение не обходит эти ограничения ОС. Если браузер заблокировал воспроизведение, появится кнопка «Включить видео и звук».

## Разработка и проверки

Нужны Node.js 22+ и npm.

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run test:e2e
npm run build
```

`npm run dev` запускает порт 3000. Камера доступна на `localhost`, но HTTP-адрес компьютера в локальной сети не считается безопасным на телефоне — используйте HTTPS deployment для проверки на телефонах. `vite preview` не запускает Vercel Functions; `/api/ice` проверяйте на Vercel или через Vercel CLI.

Модульные тесты проверяют выдачу TURN-паролей, ссылки, применение качества, привязку потока, смену камеры с сохранением звука, позднее разрешение камеры и блокировку autoplay. Браузерный тест поднимает локальные Vite и PeerServer и передаёт настоящий WebRTC-поток между двумя страницами размера телефона с синтетическими камерой и микрофоном. Для него требуется установленный Google Chrome (`channel: chrome`). Это не заменяет проверку реальных iPhone/Android и TURN в мобильных сетях.
